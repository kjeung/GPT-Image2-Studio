# GPT-Image2-Studio v0.3.001

`v0.3.001` 将主应用版本从 `0.3.000` 更新到 `0.3.001`。

## 更新内容

收口核对（地图 [#1](https://github.com/kjeung/GPT-Image2-Studio/issues/1)）发现重建 `v0.2.116`
基线时有三处 fork 能力静默丢失，本次一并补回：

- **生成容错**（[#14](https://github.com/kjeung/GPT-Image2-Studio/issues/14)）：有的中转会把上游
  长 JSON 拦腰折成多条 SSE `data:` 行，按规范拼回后字符串中间凭空多出换行，
  `JSON.parse` 直接报 "Bad control character in string literal"；另有中转原样透传带裸控制字符
  的 JSON。现在按「规范拼法 → 折行兜底拼法 → 控制字符修复」的顺序解析，两种故障都能兜住，
  合法的多行 `data:` 也不会被粘连。
- **胶片条批量下载**（[#15](https://github.com/kjeung/GPT-Image2-Studio/issues/15)）：生成结果
  上方的胶片条支持多选、全选、取消与「下载所选」，逐张保存而不是打一个压缩包。胶片条的勾选
  集与画廊的勾选集相互独立，互不影响「删除选中」的目标。
- **灯箱「载入配置」**（[#15](https://github.com/kjeung/GPT-Image2-Studio/issues/15)）：图片
  详情里可以直接把这张图的提示词、参数**与参考图**搬回生成区域。
- **画廊自绘滚动轨**（[#15](https://github.com/kjeung/GPT-Image2-Studio/issues/15)）：瀑布画廊
  恢复可拖动、带上下箭头的滚动条，长列表里比原生滚动条更好用。

另修一个纯性能缺陷：元数据修复与提示词预览保存的「写完回读这一条」不再重扫整个归档，
300 张图时从约 400ms 降到约 5ms。

## 兼容性

- 无需迁移：配置、生成记录与图片资产的结构都没有变。
- 交互有一处可见变化：胶片条上方新增一排批量选择按钮，默认收起；
  画廊右侧恢复滚动轨。

## 版本规则

- 普通更新：更新位 +1。
- 版本格式为 `major.minor.patch`，patch 固定三位数字；上级版本变化时，下级版本归零。

## 升级说明

- 既有配置、生成记录和图片资产不需要迁移。
- 商品图采集扩展使用独立版本线，本次主应用更新不会修改扩展版本。

## 验证

- 发布前需运行项目测试、构建、发行一致性检查和 OpenSpec 严格校验；实际结果以本次发布交付记录为准。
